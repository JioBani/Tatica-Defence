# 컨벤션 점검 (테스트 슬롯) — stat-unit-range

> 점검 기준: `requirement-test/convention.md` (UT-1~UT-4) + Unity 에드온 §요구사항 테스트 보강.
> 점검 대상: 본 구현 단위에서 test 멤버가 작성·수정한 테스트 산출물만. 프로덕션은 impl 영역(제외).

| 파일 | 작성 성격 |

## Pass 1 — 위반 식별

### UT-1 (AAA 구조 명료성)
- `StatUnitRangeTests`: Arrange(`new UnitStat(...)`/`new UnitStatSheet()`)·Act(`SetBaseValue`/`FormatStatValue`/`Init`)·Assert 빈 줄 분리. 메타데이터 정의 검증(S8)은 Act+Assert 2단으로 구분. → 위반 없음.

### UT-2 (매직 입력값 → 의미 있는 변수명)
- 의미 이름화: `attackPower`·`fractionalSpeed`·`expectedDefault`·`rawBase`·`expectedFinal`·`defenseRatio` 등. `[TestCase]` 인라인 경계값은 의미(// 방어력 ≤ 95% 등) 주석 병기. → 위반 없음.

### UT-3 (테스트 한 개당 한 동작)
- 각 메서드 단일 동작. DoD-S9 상한/하한/정수화/실수/수정자후 강제를 각각 별 메서드로 분리. DoD-S10 표시·메타 정합을 2테스트로 분리. `Test_S10_SheetStatsCarrySameMetadataAsCatalog` 의 10종 순회는 *한 동작(시트 메타가 카탈로그와 일치)* 의 도메인 순회 → 허용. → 위반 없음.

### UT-4 (매개변수화 테스트 활용)
- 동치분할·경계값·결정테이블을 `[TestCase]`/`[TestCaseSource]` 로 압축. S8 정의 표는 상한 ∞(`float.PositiveInfinity`, 비-const) 때문에 인라인 `[TestCase]` 불가 → `[TestCaseSource]` 소스 메서드로 10행 공급(`SetName` 으로 케이스 식별). 케이스 의미가 흐려지지 않는 선에서만 통합. → 위반 없음.

### 갱신 3개 파일
- `UnitStatTests`: 새 생성자 시그니처 정렬 + 계산 로직 격리를 위한 비클램프 메타데이터 헬퍼(`AdditiveMeta`/`SepMultMeta`) 도입. 기존 테스트 구조·의도(가산/증감분리 계산 검증) 보존. → 신규 위반 없음.
- `UnitStatKindHelperTests`: `FormatStatValue` 수신자만 `StatUnit` 으로 정렬, GetDisplayName 테스트 유지. → 신규 위반 없음.
- `DamageCalculatorTests` ②갱신분: 방어력 ≤95% 클램프로 무효해진 "방어력 150%→데미지 0" 전제를 유효 경로(공격력/baseDamage 0 → 0)로 재타겟. AAA·명명 보존. → 신규 위반 없음.
