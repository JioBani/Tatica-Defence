# 테스트케이스 명세 — stat-set-unification (Task-2, SR 그룹 A)

> 구현 단위 `stat-set-unification` 의 요구사항 테스트 케이스 도출 근거.
> 검증 기준: UR Req-2·4 / SR DoD-S1~S7 의 완료 정의(코드 추종 금지).
> 테스트 코드: `Assets/Tests/Editor/StatSetUnificationTests.cs` (EditMode, 순수 로직 → EditMode 격리).

## 범위 경계

- **본 단위 대상**: DoD-S1·S2·S3·S4·S5·S6·S7 (능력치 종류 집합 10종 단일화 + 단일 채널 데미지).
- **본 단위 범위 밖**: DoD-S8·S9·S10 (능력치 단위·범위·클램프·표기 단일진실) — Task-3(Group B) 책임이므로 본 명세에서 테스트하지 않는다.

## 테스트 격리 단위 결정

| DoD | 검증 표면 | 격리 단위 | 사유 |
|-----|-----------|-----------|------|
| S1·S2 | `UnitStatKind` enum 종류 집합 | EditMode | 순수 enum 메타데이터(리플렉션). Unity 라이프사이클 무관 |
| S3·S7 | `DamageCalculator` 파이프라인 | EditMode | 순수 정적 계산. 스탯 시트는 `new` 생성 |

## 테스트 케이스 도출

### DoD-S1 — 종류 단일 진실이 정확히 10종만 열거

- **유스케이스(정상)**: enum 종류 수 = 10. → `Test_S1_EnumHasExactly10Kinds`
- **유스케이스(정상)**: enum 종류 집합 = 명세 10종과 정확히 일치(EquivalentTo). → `Test_S1_EnumContainsExactlyThe10SpecifiedKinds`
- **예외 흐름(제거 확인)**: 상태저항력·받는 피해 감소 부재. 동치분할[제거 대상]을 `[TestCase]` 로 압축. → `Test_S1_RemovedKindsAbsentFromEnum`

### DoD-S2 — 단일 공격력·단일 방어력(물리/마법 분리 없음)

- **동치분할[무효=분리 종류]**: PhysicalAttack·MagicAttack·PhysicalDefense·MagicDefense 4종 부재. `[TestCase]` 압축. → `Test_S2_SplitAttackDefenseKindsAbsent`
- **동치분할[유효=단일 종류]**: Attack·Defense 존재. `[TestCase]` 압축. → `Test_S2_SingleAttackAndDefenseKindsPresent`

### DoD-S3 — 데미지 계산이 단일 공격력·단일 방어력 채널만 사용

- **유스케이스(정상)**: 단일 공격력이 기본 데미지 출발점(데미지 타입 분기 없음). 공격력 100·방어 0 → 100. → `Test_S3_DamageUsesSingleAttackChannel`
- **유스케이스(정상)**: 단일 방어력으로 경감. 방어 0.3 → ×0.7 = 70. → `Test_S3_DamageReducedBySingleDefenseChannel`
- **유스케이스(대안=스킬 경로)**: 평타·스킬이 동일 단일 공격력 소비. 스킬계수 1.5 → 100×1.5 = 150. → `Test_S3_SkillPathConsumesSameSingleAttackChannel`

### DoD-S7 — 받는 피해 감소 단계 제거, 입히는 피해 증가 유지

- **유스케이스(정상)**: 입히는 피해 증가 유지. 0.2 → ×1.2 = 120. → `Test_S7_DamageDealtIncreaseStillApplied`
- **예외 흐름(제거 확인)**: 받는 피해 감소 단계 부재. 전체 요인(치명타·방어·피해증가) 적용 시 받는 피해 감소 곱(×0.9) 미포함. 100×1.5×0.7×1.2 = 126 (정정 전이라면 ×0.9 추가되어 113). → `Test_S7_NoDamageReductionStepInPipeline`

### DoD-S4 — 스탯 시트 보유·조회·순회 집합이 10종과 일치

- **유스케이스(정상)**: `Enumerate()` 가 10종 집합과 정확히 일치(EquivalentTo). → `Test_S4_SheetEnumeratesExactlyThe10Kinds`
- **유스케이스(정상)**: 10종 각각 `Get(kind)` 가 non-null. (결정 테이블[종류×조회결과]을 enum 순회로 압축) → `Test_S4_GetReturnsStatForEvery10Kinds`

### DoD-S6 — 스탯 정보 패널이 10종만 표시

- **유스케이스(정상)**: 표시 집합(상단 MainStats ∪ 하단 SubStats) = 10종과 정확히 일치. → `Test_S6_StatInfoPanelDisplaysExactlyThe10Kinds`
- **예외 흐름(중복 없음)**: 표시 집합에 중복 종류 없음. → `Test_S6_StatInfoPanelHasNoDuplicateDisplayedKinds`

### DoD-S5 — 성급별 기본 스탯 자산이 10종만 정의 + 물리 값 계승

- **테스트 한계 명시**: 물리 값 계승(`[FormerlySerializedAs]`) 은 디스크 직렬화된 레거시 `.asset` 의 역직렬화 시점에 동작한다. EditMode in-memory(`ScriptableObject.CreateInstance`) 로는 구 필드명(`physicalAttack`) 직렬화 데이터를 재현할 수 없어 계승 자체를 단위 테스트로 검증 불가.
- **간접 검증**: `GetStat(kind, star)` 의 10종 조회 표면은 `UnitStatSheetTests.Init_SetsAllStatsFromData`(10종 SO 주입 → 시트 반영)가 커버한다. 물리 값 계승의 실효 확인은 개발자 QA(에셋 마이그레이션 검증, DD §횡단 3)로 이관.
