## 범위 외 회귀

### MIS-001: ArcanistSynergyController 배치 이벤트 경로의 시너지 버프 미적용 (무관 회귀)

- 라벨: **무관 회귀 (본 구현 단위 범위 밖 — 컨트롤러 디스패치 경로)**
- 실패 테스트:
  - `Tests.Editor.ArcanistSynergyControllerTests.PlacementChanged_BattleArea_AppliesSSEToSynergyDefender` — 기대 35, 실제 10(base)
  - `Tests.Editor.ArcanistSynergyControllerTests.PlacementChanged_BattleArea_AppliesSpellPowerToNonSynergyDefender` — 기대 25, 실제 10(base)
- 기대 동작: 배치 이벤트(`OnDefenderPlacementChangedEvent`) 발행 → `SynergyController` 가 티어 활성화 후 SSE 를 Defender 의 공격력에 적용 → 공격력 = base + 주문력.
- 실제 동작: 컨트롤러 경로에서 수정자가 적용되지 않아 공격력이 base 값에 머무름(10).
- 테스트 코드: `Assets/Tests/Editor/ArcanistSynergyControllerTests.cs:85`, `:96`

**인과 점검 (요구사항 테스트 단계 — 무관 판정 근거)**:
1. 공유 의존성: 본 구현 단위가 단일화한 `Attack` 스탯에 시너지 버프가 부여된다(DD-7, 잠재적 공유).
2. 그러나 Arcanist 효과의 `Attack` 재배선은 직접 효과 테스트 3종이 GREEN 으로 독립 입증한다: `ArcanistSynergyStatusEffectTests`·`ArcanistSpellPowerEffectTests`·`GunslingerSynergyStatusEffectTests` — 모두 `effect.OnApply()` 직접 호출로 `Attack` 에 수정자가 정상 적용됨(공격력 = base + 버프).
3. 실패는 `SynergyController`/`ArcanistSynergyController` 의 **배치 이벤트→티어 활성화→Apply 디스패치** 경로에 한정되며, 이 클래스들은 본 구현 단위 변경 파일에 포함되지 않는다(변경영역.md §변경된 프로덕션 파일 1~12 에 없음).
4. 본 테스트 파일에 가한 편집은 **정합 보존 리네임**(production 버프 대상과 테스트 단언 스탯을 함께 `MagicAttack`→`Attack` 으로 일치 변경)이므로, 통과/실패 결과가 리네임에 **불변**이다 — 즉 정정 전(구 `MagicAttack` 기준)에도 동일하게 실패했을 것으로, 본 구현 단위가 새로 깨뜨린 회귀가 아니다(기존 실패로 추정).
- 결론: **DoD-S1~S7 과 무관**. 본 구현 단위(stat-set-unification)의 불일치가 아니다. 다음 단계(불일치 해소)에서 원인 분류·처리 대상.

**분류**: 무관 회귀 (out-of-scope) — 본 구현 단위(stat-set-unification)가 깨뜨린 것이 아님(①·② 어느 쪽도 본 단위 책임 아님).

**분류 사유 (baseline 판정 — 추정 아님, 인과 확정)**:
- *1순위 코드 영향면 논리 분석*: 본 구현 단위의 Arcanist 경로 변경은 효과 클래스 2종의 수정자 적용 대상(`MagicAttack`→`Attack`)뿐이다. 실패 경로(배치이벤트→`SynergyController.HandlePlacementChanged`→`ApplySSEToDefender`→`StatusEffectController.Apply`→`SSE.OnSynergyActivated`→`ApplyModifier`)에서 `SynergyController`·`ArcanistSynergyController`·`StatusEffectController`·티어 활성화·이벤트버스는 본 구현 단위에서 변경하지 않았다(변경영역.md §변경된 프로덕션 파일에 없음 — 컨트롤러 코드 직접 확인 완료).
- *2순위 git log*: `ArcanistSynergyControllerTests.cs`·`ArcanistSynergyController.cs`·`SynergyController.cs` 모두 기존 티켓(TACD-252/254/263/260) 산물로, Task-2 와 무관.
- *empirical 확증 (impl 직접 재실행, UnityMCP run_tests EditMode)*: 같은 3개 그룹 13케이스 중 직접효과 11개 전부 GREEN(`ArcanistSynergyStatusEffectTests`·`ArcanistSpellPowerEffectTests` 포함), 컨트롤러 2개만 FAIL(`actual=10=base` — 수정자 자체가 미적용). 즉 `Attack` 적용 메커니즘은 정상 작동하며, 실패는 변경하지 않은 디스패치 경로에서 수정자가 *부여되지 않아* base 에 머무는 것이다.
- *결론*: 직접효과가 GREEN 이라는 것은 production 버프 대상과 테스트 단언 스탯이 일치하게 리네임됐음을 입증한다(리네임 정합). 따라서 컨트롤러 실패는 채널(MagicAttack/Attack)과 무관한 경로 문제이며, 정정 전(구 `MagicAttack` 기준)에도 동일하게 실패했을 채널-무관 기존 실패다. 본 구현 단위가 새로 깨뜨린 회귀가 아니다.

**처리**: out-of-scope 로 확정하여 본 구현 단위 불일치 해소에서 제외(① 수정 대상 아님). 컨트롤러 배치이벤트 디스패치 경로의 수정자 미적용은 test 셋업 문제(②) 또는 컨트롤러 잠재 결함 가능성이 있으나 채널-무관 기존 문제이므로, 본 구현 단위와 분리하여 **별도 추적(후속 조사/티켓)** 을 권장한다. (테스트 코드 본문은 본 단계 격리 원칙상 미열람 — ②/잠재결함 구분은 test 멤버 영역.)
